# Google Doc → Notion newsletter sync

This Google Apps Script watches the [Daily Newsletter Digest - Editions Queue](https://drive.google.com/drive/u/0/folders/1mhNmOwgL3lBMlrWAdNZQNiHZ3uZ-Lk9o) folder. Gemini Spark creates one dated Google Doc there and rewrites it at 8am, 12pm, 4pm, and 8pm. The script saves each pass privately, then once a night, after 10pm New York time, publishes the **full edition** (every pass, stacked in order) as one Notion Editions page and one Google Doc in a **Daily Newsletter - Full Editions** Drive folder. The website shows that page as one Email message.

## One-time connection

1. While signed into the **West Shore** Google account, open [Apps Script](https://script.google.com/home/projects/create). Name the project `Daily Newsletter → Notion`.
2. Replace the default `Code.gs` with this directory's [Code.gs](Code.gs). In **Project Settings**, enable **Show appsscript.json manifest file in editor**, then replace the manifest with [appsscript.json](appsscript.json). Save both files. The manifest gives Google read-only access to Drive, plus `drive.file`, which only lets the script create and edit files it made itself (the Full Editions folder and its Docs). It also allows external requests and trigger management.
3. In Notion, create a **separate internal connection** with **Read content**, **Insert content**, and **Insert property** capabilities. Share only the **Daily Newsletter Digest → Editions** database with it. Keep the website's existing read-only Notion connection unchanged.
4. In Apps Script, open **Project Settings → Script properties → Add script property**. Set the name to `NOTION_TOKEN` and the value to the new Notion connection's token. Do not put the token in code, Git, or chat.
5. Run `checkNewsletterConnections` once. Google will ask you to authorize read-only access to your Drive, access to files the script creates, external requests, and trigger management. Confirm the account and permissions yourself. The execution log should say the connections work and link the Full Editions folder it created in My Drive. Move that folder anywhere you like; the script finds it by ID. If it is trashed, the script makes a new one.
6. Run `syncNewsletterDocs` once. It will backfill missing older Docs while skipping titles already in Notion.
7. Run `installNewsletterTrigger` once, unless the Triggers page already shows one time-based `syncNewsletterDocs` trigger. The existing trigger checks every 15 minutes. Check **Executions** for errors.

For a Doc whose filename ends with today's written date (for example, “Thursday, October 1, 2026”), each 15-minute check from 8am **America/New_York** exports the Doc when it has changed and saves it as that window's pass (8am, 12pm, 4pm, or 8pm) in Script properties, split into small chunks. A rewrite later in the same window replaces that pass; earlier passes stay frozen. A window where Spark never rewrote the Doc gets no duplicate pass. If Spark ever appends instead of rewriting, only the new part is kept. Nothing reaches Notion before 10pm. The first check after 10pm stacks the passes with a divider between them, creates the Notion page in one call (falling back to 100-block batches if Notion refuses the Markdown), saves the Drive Doc, marks the date published, and clears the saved passes. A missed night publishes at the next check from the saved passes. Saved passes and markers older than seven days are pruned. Pages that the older four-pass version had already started are finished in that toggle format.

Spark must actually put today's Doc in the queue. If it does not, no edition can appear. Check Spark's task and schedule status, then check the queue for a dated Google Doc before troubleshooting this sync.

The script uses the Google Doc filename as the Notion page title, removing a trailing `.md`. It refuses a short Doc or one with private inbox/Notion links. Existing historical pages remain unchanged and retain their original IDs; previously missed older Docs still import once. A pre-existing page with the same title is never overwritten by the snapshot workflow.

The website's GitHub workflow reads Notion on its own schedule (its late-night run is 3:30 UTC: 10:30pm EST, 11:30pm EDT), so the full edition appears after that run plus Pages deployment time. A failed Notion/Drive read does not create a blank edition. The existing website snapshot remains available if its own feed job fails.
